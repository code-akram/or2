# or2 v0.1.5 candidate

Signed candidate installed on the owner's phone on 2026-10-04 with explicit approval. **Not publicly
released or tagged.** Android 14 or later, arm64; revised versionCode 8, FFI API 22. Updates v0.1.4 in place;
no database migration, daemon, re-pairing or host authorization change.

## Changes

- **Project directories.** The host picker's **Dirs** tab merges live herdr agent/pane working directories
  (including Pi/plain shells, default/named sessions) ahead of recent Claude Code/Codex paths. Live rows update
  from the same current-host watches as herdr, without another query; history failure/loading does not hide them.
  Tap one to open a new shell there with the host's transport preference. Rust validates/deduplicates/caps the
  combined paths (API 22); missing or malformed history does not block other pickers.
- **Pairing lock release.** Guards explicitly unlock on drop, including when another process inherited
  the descriptor between fork and exec. Ended runs no longer look live because of that inheritance.
- **SFTP fixture cleanup.** The test server stays passive after EOF so it reliably observes the client's
  channel Close. This changes fixture code, not the app's SFTP behavior.

History reads are bounded to five seconds, a 256 KiB Claude history tail and the first record (up to
64 KiB) of up to 64 recent Codex rollout files. Codex's combined output budget is 512 KiB, so large headers
can exhaust it before all 64 files; the final partial record is ignored. At most 20 distinct paths leave Rust. Only literal, visible absolute
paths can be opened; quotes and shell metacharacters remain data, never command code. Archived Codex sessions,
nonstandard history formats and tmux-in-directory creation are not included in this first version.

The first candidate discarded realistic Codex `session_meta` records: real headers on both hosts are
about 19–23 KiB, but the reader took only 8 KiB and required complete JSON. Complete Claude records also
had that parser cap. The revised reader uses the bounds above and still rejects partial, malformed and
unsafe records rather than accepting JSON fragments.

### Owner QA fix: live herdr directories (versionCode 8, FFI API 22)

The history-reader fix did not address another gap: Dirs never consumed the live working directories already
shown correctly in herdr. A device regression reproduced this exactly on the old code: a live Pi path was
visible in herdr, then absent when switching to Dirs. The live Arch snapshot also contained additional cwd
not represented by history. The revised picker merges current watched metadata, including non-agent panes,
before history, with automatic updates and no new I/O or storage.

- Rust's pure `merge_directory_paths` FFI export owns literal-path rejection, exact dedup and the combined
  20-path cap. The app supplies the same per-host views used by herdr, default then named sessions, picker agent
  order with pane fallback then all panes. No path sanitation, title guessing or tilde expansion. JNI/FFI calls
  use at most 20 accepted paths plus 32 bounded candidates, so large views need no bulk copy across the boundary.
- Fresh-context Codex design/patch/fix/scope reviews completed. The bulk-input concern was fixed and tested;
  multi-agent pane fallback/order is tested. Final patch and current-watch scoping reviews had no actionable
  findings. Scoped metadata always comes from the current owned Live watch, not buffered values from another
  host, retired connection, stopped watch or lagging version.
- **1,067 Rust tests**, **661 JVM tests** (no failures/errors/skips), formatting, Clippy, both generated checks,
  Android debug/device-test/signed-release builds and both lints pass. Rust/JVM tests cover validation, order,

- **`OK (169 tests)`** on the separate device-test app, in 375 s. Live Pi/plain-shell paths, cwd changes,
