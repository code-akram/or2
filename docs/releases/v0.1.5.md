# or2 v0.1.5

Project directories and one-tap shells. Updates v0.1.4 in place, preserving hosts and Keystore-bound keys.
Android 14 or later, arm64; versionCode 8, FFI API 22. No database migration, daemon, re-pairing or host
authorization change.

## What's new

- **Dirs in the host picker.** Live herdr agent/pane working directories (including Pi and plain shells,
  default and named sessions) come first, followed by recent Claude Code/Codex projects. Live paths follow
  the same current-host watches as herdr, without extra queries or polling. History loading/failure cannot
  hide live directories. **Refresh** reads history again without reconnecting.
- **One-tap project shells.** Tap a directory to open a new shell there with the host's transport preference.
  Rust validates literal paths, exact-deduplicates and caps the combined list at 20. Paths are never sanitized,
  inferred from titles or expanded from `~`; shell metacharacters remain data. A missing directory exits
  visibly rather than silently opening at home. herdr, tmux and the plain Shell pill remain unchanged.
- **Realistic history records.** Codex headers with large instructions no longer disappear at an 8 KiB limit.
  Discovery allows complete headers up to 64 KiB, with a combined 512 KiB Codex output budget, and complete
  Claude entries within the existing 256 KiB tail. Partial, malformed and overlong records are still ignored.
- **Pairing lock cleanup.** Explicit unlock on drop prevents an inherited descriptor from keeping an ended
  pairing run looking live. A separate SFTP fixture fix makes channel-close tests reliable; it does not change
  the app's SFTP behavior.

History discovery remains read-only, on the existing SSH connection, bounded to five seconds and a 1 MiB
per-stream exec cap. It examines up to 64 recent Codex rollout files; large headers can exhaust the output
budget sooner. Archived sessions, nonstandard history formats and tmux-in-directory creation are not included.
Login startup files can intentionally change the shell's working directory.

## Install

**The app.** Download `or2-v0.1.5.apk` and install over the previous signed release. Do not uninstall or clear
the daily app. SHA-256:

```text
9f35619e3bd4e5827cb239d0ec60d24d3445e910de64f1d795f1840761d5dff3  or2-v0.1.5.apk
```

Check with `sha256sum or2-v0.1.5.apk`. Debug APKs use a different signing key and cannot update the signed app.

**`or2-pair`.** Existing host installations keep working; no re-pairing is needed. Linux x86_64/aarch64 and
macOS Intel/Apple silicon binaries are available through the checksum-verifying installer:

```sh
curl -fsSL https://raw.githubusercontent.com/code-akram/or2/main/scripts/install-or2-pair.sh | sh
```

From source: `cargo install --git https://github.com/code-akram/or2 --tag v0.1.5 or2-pair --locked`.
