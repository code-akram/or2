or2 v0.1.0 is the first release: the Android app as a signed APK, and `or2-pair`, the host side of Easy
pair, for Linux and macOS. It is an early release of a tool its author uses every day; read the known
shortcomings before relying on it.

## What or2 is

A free, open-source (GPL-3.0-or-later) Android client for SSH and mosh, built for driving coding agents that
run in tmux or herdr on your own machines. The phone is a remote control for agents, not a small desktop: a
reliable terminal, your multiplexer sessions as native lists, and one inbox for every agent on every host.
Keys only, no account, no cloud, no Google Play Services.

## What works

- **Terminal** (M1): SSH with Ed25519 keys generated in the app or imported (passphrases included), kept in
  the Android Keystore behind a biometric unlock; first-use and changed host-key prompts; a terminal rendered
  by libghostty-vt with IME input, a key toolbar, an arrow pad, a composer, selection, scrollback and pinch
  zoom.
- **Multiplexers** (M2): one SSH connection per host carries every terminal; tmux sessions (attach, create);
  herdr sessions and panes; hosts with several addresses (LAN, ZeroTier, …) raced, the first to answer wins.
- **herdr agent inbox**: the agents of every host, blocked first, live; tap one to open its pane and answer
  from the composer.
- **Stays connected** (M3): mosh terminals that roam across network changes and survive the SSH connection
  dropping; a foreground service that keeps sessions open in the background; automatic reattach to the last
  pane, also after the app's process was killed.
- **Easy pair v2**: run `or2-pair` on the host, type the code the phone shows, scan the QR. It pairs over the
  SSH port you already use (no extra port, no firewall rule); the host key is trusted from the scan, so there
  is no first-use prompt. `--manual` and a manual setup form remain for hosts it cannot pair.
- **One add-host chooser**: the empty Home, the empty inbox and **+** offer the same two choices (Easy pair
  with QR, Set up manually), and the manual form can make a new key.
- **No permission dialogs while connecting**: the battery-optimisation exemption is the last step of adding a
  host, asked once; the notification permission is offered by a card on Home, and the service runs without it.
- **Compact UI** everywhere (type, controls, popups, a small terminal font), in Catppuccin Mocha.
- **`or2-pair` checks** print the exact fix for the host: how to start sshd, the install command of its
  package manager, the rule for its firewall, and what in `sshd_config` would keep the phone out.

## Install

**The app.** Download `or2-v0.1.0.apk` from this release and install it (Android 14 or later, arm64). It is
signed with the or2 release key. SHA-256 of the APK:

```text
385df1e3f9e3cb30fa236bf7f12928889956dab3705d971c82f76d294de5ac44  or2-v0.1.0.apk
```

Check it with `sha256sum or2-v0.1.0.apk` before installing. A development (debug) build of or2 is signed with
a different key, so this APK cannot be installed over one: uninstall the debug build first. That deletes its
hosts and its keys, which are bound to the phone's Keystore and never exported; pair the hosts again.

**`or2-pair` on a host** (Linux x86_64 or aarch64, static; macOS Intel or Apple silicon), into
`~/.local/bin`, no `sudo`:

```sh
curl -fsSL https://raw.githubusercontent.com/code-akram/or2/main/scripts/install-or2-pair.sh | sh
or2-pair
```

The script installs the binary for your OS and CPU from the latest release, checks it against the release's
`SHA256SUMS`, runs it once and only then puts it in place. `--version v0.1.0` installs this release
explicitly. To read the script first, download it and run it with `sh`. Without the script: download
`or2-pair-<target>` and `SHA256SUMS` from this release and check them with
`grep ' or2-pair-<target>$' SHA256SUMS | sha256sum -c` (macOS: `shasum -a 256 -c`). From source:
`cargo install --git https://github.com/code-akram/or2 or2-pair --locked`. See
[Pair a host](https://github.com/code-akram/or2/blob/v0.1.0/docs/pairing.md).

## Known shortcomings and untested areas

Stated plainly, so nobody finds them the hard way:

- **Networks.** Tested on Wi-Fi with the phone plugged in. Mobile data, the Wi-Fi to mobile data handover,
  and background runs while the phone is unplugged (Doze) are not yet tested, so the v0 acceptance test
  (10 minutes in the background over mobile data, then back to the same pane) has not been passed yet.
- **Mac hosts.** A Mac is not yet verified with Easy pair v2, and the macOS `or2-pair` binaries were built by
  CI and have not yet been run on a Mac. A sleeping Mac must be woken by hand (Wake-on-LAN and a TCP wake
  probe are on the M4 backlog); a MacBook with its lid closed on battery cannot be reached at all.
- **Easy pair**: its phone acceptance checklist is not complete. Windows hosts get no automatic key install:
  `or2-pair` prints the code and you add the key line by hand. The static Linux binaries see only accounts in
  `/etc/passwd`; an account from LDAP, SSSD or systemd-homed needs the source build. Copying the SELinux label
  of `authorized_keys` is untested on a real SELinux host.
- **Installer**: the SHA-256 check proves the download is intact, not who made it, because the binary and
  `SHA256SUMS` come from the same GitHub release. Signed releases are a future item.
- **Not there yet**: agent notifications; image paste (SFTP); voice input; Chat View; jump hosts (ProxyJump)
  and embedded ZeroTier (connections are direct: LAN, a ZeroTier or other VPN app, a public address); tmux
  control mode (windows and panes as native tabs); key export or backup (by design keys never leave the phone,
  so uninstalling the app loses them).
- **Terminal limits**: mosh keeps no scrollback of its own (it syncs only the screen), so history inside a mosh
  terminal comes from tmux or herdr; a hardware keyboard bypasses the IME (no CJK composition from it); DECCOLM
  column switching is unsupported; the worst full-screen redraws can exceed a 60 Hz frame at p95.
- **Distribution**: arm64 Android 14+ only; not on F-Droid yet (the build has no Google Play Services or FCM,
  so it can be).

## What's next

Agent notifications from herdr events, image paste over SFTP, voice dictation without Google services,
Wake-on-LAN and the TCP wake probe (M4), then Chat View, a diff viewer and web preview (M5). See the
[roadmap](https://github.com/code-akram/or2/blob/v0.1.0/docs/roadmap.md) and the
[design](https://github.com/code-akram/or2/blob/v0.1.0/docs/design.md).
