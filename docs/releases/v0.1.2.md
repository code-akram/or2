or2 v0.1.2 is a patch release: reply to an agent straight from its notification, paste images (several at once,
about a second each), and one simpler model for the whole app, shaped by a day of the owner's QA on the phone. It
installs over v0.1.1 and keeps your hosts and keys.

## What's new

- **Reply from a notification.** Type into an agent's notification and the reply reaches its pane through herdr,
  with no terminal open; the notification then shows what was sent. The reply is bound to that exact agent
  instance (herdr's session id, or the name of an agent herdr started), so it never lands in a shell or in another
  agent. Agents need herdr's integration for this: see "Reply and herdr's integrations" below.
- **Notifications for every finished turn.** herdr reports a finished turn as `idle` instead of `done` when the
  pane counts as seen, and opening a pane from or2 makes it seen, so the usual flow (open an agent, send, lock the
  phone) never notified. A turn that ends after working now notifies `Done` whichever word herdr uses.
- **Image paste.** The composer's image button (up to 10 at once), an image from the keyboard, or Share → or2
  (several at once). or2 shrinks each image, strips its metadata (location included), uploads it over SFTP on the
  host's connection to a private `~/.cache/or2/images` (swept after seven days), and inserts the paths at the prompt
  without pressing Enter. Uploads queue per terminal ("Uploading image 2 of 4…"); one that fails doesn't stop the
  rest. An upload waits for 8 network round trips instead of 27, about a second on a distant host.
- **One model for the whole app.**
  - **Home** is the one place for hosts and their terminals: each host card shows its terminals as live
    thumbnails with **×** to close (herdr and tmux keep running on the host; a shell asks first). A tap on the host
    opens the session picker, connecting first when needed; **⋯** has Connect or Disconnect, Edit and Delete. The
    separate host screen is gone.
  - **The picker** lists the agents of each herdr session, grouped by workspace with their status and directory;
    a tap opens that agent. A session's own row is its name and agent count, as a tmux row is its name and
    windows. A session that already has a terminal is marked **● Open**, and choosing it switches to it: one
    terminal per herdr session, never a second client showing the same pane. The tmux list is fresh every time.
  - **In a terminal**, Back and the orange disc go Home; the green disc opens **Terminals**: every open terminal by
    host with its **×**, **Copy screen**, and **Gestures & shortcuts**.
  - **The toolbar**, in the owner's order and fitting the screen: `Ctrl`, `Esc`, `Tab`, `⇧Tab` (Claude Code's
    mode cycle, which Gboard cannot send), `⇧` (a Shift latch: Shift+Enter, Shift+arrows, a capital), the arrow
    pad, Paste, `/`, `@`, then the composer and keyboard toggles; Copy and Clear while selecting.
  - Multi-line text to an agent goes out as one paste with no "Send N lines?" dialog; the confirmation stays only
    where lines would really run one at a time (a program without bracketed paste).
- **Smaller things.** Blue arrow-pad keys; a tap is a mouse click in programs that track the mouse (herdr's own
  buttons work); the scroll-to-bottom button after wheel-scrolling herdr or tmux; one fixed top bar; nothing draws
  into the status bar.

Fixed on the way: a tmux swipe after switching that terminal to another session scrolled the old session; an
explicit Mosh connect could wait twice its 15 s timeout; a confirmed paste ignored bracketed paste; closing the
composer left the keys nowhere; three sheets drew rows in the wrong colour. A whole-app review removed about 670
lines of dead or duplicated code across the app and the Rust core (FFI API 18) without losing a feature.

## Reply and herdr's integrations

A notification has Reply only when herdr knows the agent's session, which it learns from its integration hook
inside the agent. `herdr integration status` lists them; install what you use, for example
`herdr integration install pi`, then restart that agent. Without it the agent still notifies (herdr reads its
state from the screen) but has no Reply. With herdr 0.9.3 the Codex hook's session report is refused by herdr
itself, so Codex gets Reply only until it restarts; that is reported upstream.

## Install

**The app.** Download `or2-v0.1.2.apk` and install it over v0.1.1 (Android 14 or later, arm64); your hosts and
keys stay. It is signed with the or2 release key. SHA-256 of the APK:

```text
7a8c9733fee8425572970012ccb118ba0c7f52d0992370a268c6514da2b0b8d6  or2-v0.1.2.apk
```

Check it with `sha256sum or2-v0.1.2.apk` before installing. A debug build of or2 is signed with a different key:
uninstall it first (that deletes its hosts and Keystore-bound keys) and pair the hosts again.

**`or2-pair` on a host** (Linux x86_64 or aarch64, static; macOS Intel or Apple silicon), into `~/.local/bin`,
no `sudo`; running it again updates it:

```sh
curl -fsSL https://raw.githubusercontent.com/code-akram/or2/main/scripts/install-or2-pair.sh | sh
or2-pair
```

The script installs the binary for your OS and CPU from the latest release, checks it against the release's
`SHA256SUMS`, runs it once and only then puts it in place; `--version v0.1.2` pins this release. From source:
`cargo install --git https://github.com/code-akram/or2 --tag v0.1.2 or2-pair --locked`.

## Verified, and still untested

- **Verified on the owner's phone** (OnePlus 10 Pro, Android 16): every item above, in the owner's QA of
  2026-10-03 on the signed build; reply from a notification to Claude Code, pi and Codex; images one and several
  at a time. The device suite passes (155 tests; the two that post notifications skip, because the test phone
  refuses the permission to a test build). Codex reviewed the release in four rounds; the last found nothing.
- **Still untested**: mobile data, the Wi-Fi to mobile data handover, and background runs while the phone is
  unplugged (Doze); so the v0 acceptance test is still open.
- **Limits that remain**: Reply to an agent herdr did not start is typed after guarded checks, so an agent that
  exits within about one network round trip after them gets the reply in its shell (closing that needs an atomic
  herdr request); the SFTP client works with OpenSSH-compatible servers; tmux older than 2.6 gets no
  session-switching swipe; arm64 Android 14+ only; not on F-Droid yet. See the
  [changelog](https://github.com/code-akram/or2/blob/v0.1.2/CHANGELOG.md).
