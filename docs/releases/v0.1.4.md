or2 v0.1.4 is a patch release: Spaces and herdr-style agent names. It updates v0.1.3 in place and keeps your
hosts and keys. Android 14 or later, arm64; versionCode 5, FFI API 20.

## What's new

- **Spaces in a herdr terminal.** The blue disc beside Home and Terminals opens the session's spaces, tabs
  and agents. The current tab and pane are marked; tap a tab or agent to focus it in the existing terminal.
  Shell and tmux headers are unchanged.
- **Agent task titles.** Inbox, session picker, Spaces and notifications show the agent's task, from its
  terminal title. Leading status/spinner glyphs are stripped and title-only updates are limited to once a
  second; status and focus changes are not held back by that limit. Agent labels follow herdr's naming order.
- **Safer host text.** Agent titles, display names and space/tab labels are stripped of bidi and invisible
  formatting characters before display, including in notifications. Protocol identifiers and agent names
  used to identify a Reply target are not changed.
- **Safer live-test cleanup.** The mosh fixture identifies only its own loopback socket, not a server on a
  different interface using the same port, and waits for the reported server to finish its fork handover.
  This changes test code only.

FFI API 20 adds `HerdrAgent.title`, `HerdrView.focused_tab_id` and `HostConnection.focus_herdr_tab`.
There is no new database migration or host setup requirement; existing host authorization still works.

## Install

**The app.** Download `or2-v0.1.4.apk` and install it over the previous signed release;
Android preserves your hosts and Keystore-bound keys. SHA-256 of the release-signed APK:

```text
5586e541b61e443301a29da7b25ccd736e06af5f50a481aa28b7f4d091af547e  or2-v0.1.4.apk
```

Check with `sha256sum or2-v0.1.4.apk` before installing. A debug APK has a different signing key and cannot
update the signed app; do not uninstall your daily app just to install a development build.

**`or2-pair`.** No re-pairing is needed for this update, and an existing installation of the host CLI keeps
working. The usual installer obtains v0.1.4 for Linux x86_64/aarch64 or macOS Intel/Apple
silicon:

```sh
curl -fsSL https://raw.githubusercontent.com/code-akram/or2/main/scripts/install-or2-pair.sh | sh
```

The installer verifies the release's checksums and runs the binary before replacing the old one. From
source: `cargo install --git https://github.com/code-akram/or2 --tag v0.1.4 or2-pair --locked`.

## Verified, and still untested

- **Owner QA, 2026-10-04:** Spaces works as intended on the signed implementation already on the phone.
- **Rust:** the complete workspace passes at default test parallelism: 1,041 tests, with sshd, tmux, mosh
  and herdr required. Formatting, Clippy with warnings denied, and both generator `--check` modes pass.
  The mosh interop suite also passed three consecutive standalone runs after the fixture fix.
- **Android:** debug, device-test and unsigned release builds, 645 JVM tests, and debug/device-test lint pass.
  The signed release APK also builds and passes signature and package-version verification.
- **Device:** instrumentation reported `OK (164 tests)` on the OnePlus 10 Pro / Android 16. It used only
  `io.github.code_akram.or2.devicetest`; the owner's app version and update time were unchanged. Notification
  tests that require permission remain conditional and do not prove the real notification flow.
- **Host artifacts:** the Linux x86_64 binary runs and reports v0.1.4; both Linux binaries have their expected
  static, stripped ELF format. The release workflow built both macOS binaries with the expected Mach-O formats;
  all four published host binaries were downloaded and checked against `SHA256SUMS`. The aarch64 Linux and
  macOS binaries were not executed on the Linux runner.
- **Published release verified, 2026-10-04:** the downloaded APK matches the checksum above and the existing
  app's signing certificate. The public latest-release installer was fetched, compared with the repository
  script and run into a temporary directory; it installed `or2-pair 0.1.4` with its checksum verified and no
  host authorization changed. The published APK was installed on the owner's phone with `install -r`;
  versionName 0.1.4 / versionCode 5 and a successful launch were verified. Biometric unlock is still required
  to resume the connection; no reconnect acceptance is inferred from installation alone.
- **Intermittent test failures:** an SFTP channel-drop cleanup wait and the pairing state-lock expiry unit
  test each failed once under high parallel load, then passed alone and in the final full workspace run.
  Their causes still need investigation; the isolated CLI's SIGKILL/expired-pairing test passes.
- **Still deferred by the owner:** mobile data, Wi-Fi to mobile handover, and unplugged/Doze background
  acceptance. LAN success is not evidence for those paths.

A Codex review of the Spaces implementation found one bidi/invisible-character issue; it was fixed with a
test before the owner's QA. Remaining product limits are recorded in
[status](https://github.com/code-akram/or2/blob/v0.1.4/docs/status.md) and the
[v0.1.2 notes](https://github.com/code-akram/or2/blob/v0.1.4/docs/releases/v0.1.2.md).
