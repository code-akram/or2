# or2 v0.1.6

Smoother, correct terminal rendering and scrolling, exact RGB themes over SSH/Mosh, and launcher/picker
polish. Updates previous signed releases and QA candidates in place, preserving hosts and Keystore-bound
keys. Android 14 or later, arm64; versionCode 12, FFI API 23. No database migration, daemon, re-pairing or
host authorization change.

## What's new

- **Reliable scrolling and retained rows.** Row drawing commands survive HWUI discarding offscreen display
  lists, so rows return correctly instead of blank. Native moved-row frames reuse existing rows without
  reshaping cells, with ordered bases that remain correct when frames coalesce. Missing delta sequences
  request a full snapshot and remain in recovery until it arrives, including across detach/remount.
- **Less UI-thread work.** Native frame pulls and UniFFI decoding run on a worker with a bounded,
  ordered handoff to vsync. Glyphs, synthetic bold, backgrounds and decorations are batched; immutable
  row display lists are cached across scrolling. No-op wheel input avoids unnecessary redraws.
- **Matching terminal colours.** Tokyo Night default background, foreground and ANSI colours match herdr;
  the app UI remains Catppuccin Mocha. SSH and Mosh launches advertise `COLORTERM=truecolor`, so programs
  such as Pi retain their exact RGB themes instead of quantizing to 256 colours. Neither host themes nor
  stored settings are edited. Open a new shell and start/resume the program there to inherit the marker;
  existing processes retain their old environment. Login startup and literal project paths are preserved.
- **Launcher and splash.** A white, blocky or2 mark on black replaces Android's default icon, with a
  monochrome layer for themed icons and a minimal fading launch splash.
- **Picker polish.** Lowercase `shell` and `dirs`; the shell pill matches the tab capsule's 32 dp height.
  Shell/tab actions and directory discovery are unchanged.

## Install

**The app.** Download `or2-v0.1.6.apk` and install over the previous signed release. Do not uninstall or
clear the daily app. SHA-256:

```text
31c3266ba0503f17d55dd508dbcb0e6e578a9d678e5d2a238069e89ce609b38f  or2-v0.1.6.apk
```

Check with `sha256sum or2-v0.1.6.apk`. Debug APKs use a different signing key and cannot update the signed app.

**`or2-pair`.** Existing host installations keep working; no re-pairing is needed. This release changes
its version, not pairing behavior. Linux x86_64/aarch64 and macOS Intel/Apple silicon binaries are available
through the checksum-verifying installer:

```sh
curl -fsSL https://raw.githubusercontent.com/code-akram/or2/main/scripts/install-or2-pair.sh | sh
```

From source: `cargo install --git https://github.com/code-akram/or2 --tag v0.1.6 or2-pair --locked`.

## Verified, and still untested

- **Owner QA, 2026-10-05:** rendering/scrolling accepted (“rendering and scrolling is solved”), Mac/Arch
  colour matching accepted (“good, its solved”), and picker polish accepted before the request to publish.
  This acceptance was on the preceding signed QA builds; the release version bump adds no feature changes.
- **1,080 Rust workspace tests**, no failures/ignored, with sshd, tmux, mosh and herdr required; formatting,
  Clippy with warnings denied, and both generator checks pass. Disposable SSH/Mosh regressions verify exact
  RGB and the inherited capability in plain/directory shells; independent native frame oracles cover scrolling.
- **675 JVM tests**, no failures/errors/skips; debug, device-test and signed release builds and both lints
  pass. All 183 Gradle tasks reran rather than relying on cached test results. The host native contract reports
  0.1.6/API 23; the packaged-native device test also asserts that exact version/API.
- The release device attempt recorded **179 cases: 176 passed, one About/license-screen failure and
  two notification-permission skips**. Logcat records a Home gesture entering the launcher while the
  license-list test was running, followed by its missing-Compose-hierarchy failure. The remaining cases,
  including packaged 0.1.6/API 23 and terminal/picker regressions, passed. ADB then stopped responding
  during cleanup; this attempt is not claimed as a passing full suite. The preceding renderer QA suite
  passed 176 cases with two permission skips; the subsequent focused native/terminal and picker suites
  passed 13 and 22 cases. The final interrupted case rerun and phone update await the existing ADB link.
- The signed APK's version and matching existing signing certificate are verified. Public-artifact and
  final installed-APK verification will be recorded after publication/installation; installation is not
  claimed while the ADB connection is unavailable.
- Linux `dist --expect-version 0.1.6` passes: both static, stripped architectures/checksums verified;
  x86_64 runs and reports 0.1.6, aarch64 is format-checked only. macOS binaries are built on macOS by the
  release workflow; cross-architectures are not claimed to have executed locally.
- **Still owner-deferred:** mobile data, Wi-Fi handover and unplugged/Doze acceptance. No host authorization,
  bridge/tunnel or security-setting changes were made during the release cycle.
