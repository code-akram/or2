# or2 v0.1.7

A demo of the app at the top of the README, and the tooling that makes it. The app itself is unchanged
from v0.1.6 apart from its version: same features, same FFI API 23, no database migration, daemon,
re-pairing or host authorization change. Updates previous signed releases in place, preserving hosts and
Keystore-bound keys. Android 14 or later, arm64; versionCode 13.

## What's new

- **A demo GIF in the README.** The real app on a phone, about 30 seconds: two hosts with live terminal
  previews, the agent inbox across both, a tap on a blocked agent that opens its pane, an answer from the
  composer while the agent finishes its work, herdr's Spaces sheet, and the session picker. Captions name
  each step and soft marks show every touch.
- **Made from invented data, reproducibly.** `ReadmeDemoDeviceTest` drives the real app through a scripted
  world (hosts `atlas` and `build-box`, herdr agents, tmux and shells) behind the app's connector, so no
  network, key or real host is involved and nothing private is filmed. It runs only when asked and is skipped
  in suite runs. `cargo xtask demo-gif` renders the recording into the GIF, and `demo-gif --check` joins the
  checks. How to record it again is in [build.md, "README demo"](https://github.com/code-akram/or2/blob/v0.1.7/docs/build.md#readme-demo),
  including a full-screen video made with the phone's own screen recorder.

## Install

**The app.** Download `or2-v0.1.7.apk` and install over the previous signed release. Do not uninstall or
clear the daily app. SHA-256:

```text
2f342ff1cc50d454ae0f266cb2f162ad9bd85c837ccc42e6c30cc9fd6c8881b5  or2-v0.1.7.apk
```

Check with `sha256sum or2-v0.1.7.apk`. Debug APKs use a different signing key and cannot update the signed app.

**`or2-pair`.** Existing host installations keep working; no re-pairing is needed. This release changes
its version, not pairing behavior. Linux x86_64/aarch64 and macOS Intel/Apple silicon binaries are available
through the checksum-verifying installer:

```sh
curl -fsSL https://raw.githubusercontent.com/code-akram/or2/main/scripts/install-or2-pair.sh | sh
```

From source: `cargo install --git https://github.com/code-akram/or2 --tag v0.1.7 or2-pair --locked`.

## Verified, and still untested

- **1,087 Rust workspace tests** (the 1,080 of v0.1.6 and seven for `demo-gif`), no failures or ignored,
  with sshd, tmux, mosh and herdr required; formatting, Clippy with warnings denied, both generator checks and
  `demo-gif --check` pass.
- **675 JVM tests**, no failures, errors or skips; debug, device-test and signed release builds and both lints
  pass, with all 183 Gradle tasks rerun. The host native contract reports 0.1.7/API 23. The release APK is
  signed by the same certificate as v0.1.6 (SHA-256 `1418c4aa…a2a2`) and reports versionCode 13, versionName
  0.1.7.
- **Device suite on the separate device-test app: 180 cases, 176 passed, three skipped** (the demo recording
  and the two notification-permission cases), **one failure**: a pixel check above the terminal in
  `TerminalVisualDeviceTest` found another colour once. It then passed five times (three alone, twice with
  its class), and the packaged 0.1.7/API 23 test passed. A second full run passed its first 162 cases before
  the phone's USB link reset dropped the stream; the 15 cases it had not reached passed on their own. The
  daily app's version and update time stayed unchanged; the test packages were removed afterwards.
- The demo GIF was looked through frame by frame: no status bar, notification or real data in it.
- Linux `dist --expect-version 0.1.7` passes: both static, stripped architectures and checksums; x86_64 runs,
  aarch64 is format-checked only. macOS binaries are built on macOS by the release workflow.
- The signed release has **not** been installed on the owner's phone; install it from this page.
- **Still owner-deferred:** mobile data, Wi-Fi handover and unplugged/Doze acceptance.
