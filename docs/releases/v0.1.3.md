or2 v0.1.3 is a patch release: zero-config Reply. Replying to an agent from its notification needs herdr on the host
and herdr's integration inside the agent; or2 now sets both up for you, and you only confirm. It installs over
v0.1.2 and keeps your hosts and keys.

## What's new

- **`or2-pair` recommends herdr.** A host without herdr is now a warning, not a quiet note: or2's agents inbox,
  notifications and Reply need it. It gives herdr's own install command
  (`curl -fsSL https://herdr.dev/install.sh | sh`, or Homebrew, mise, Nix) and never runs another project's
  installer itself. Pairing goes on either way.
- **`or2-pair` sets up Reply for the agents on the host.** After its checks it asks herdr which integrations are
  installed, finds the agents installed on the host whose integration is missing or outdated, and asks once:
  `Set up Reply for pi, opencode? [Y/n]`. Yes runs `herdr integration install` for each and says how each went;
  running sessions of those agents load it when they next start. Agents already set up are one line
  (`Reply ready for claude, codex`). Without a terminal, with `--check` or `--manual`, or on no, it prints the
  commands instead; an answer it doesn't understand counts as no.
- **Enable Reply from the phone,** for hosts you paired before: an agent with no Reply because its integration is
  missing on the host (pi, opencode, …) gets **Enable Reply** in its Inbox row and in its notification. One
  confirmation (`or2 installs herdr's pi integration on archlinux. Restart pi afterwards.`), then or2 runs
  `herdr integration install <id>` on the host over the existing connection and says the outcome. The
  notification's action only opens the app to that confirmation; only herdr's own integration names can be
  installed, as one command with no shell in between.
- **Why Codex may have no Reply, said plainly.** Codex 0.160 runs its herdr hook inside a shared background daemon
  that keeps the pane id it was first started from, so herdr refuses its session reports
  ([herdrdev/herdr#4649](https://github.com/herdrdev/herdr/issues/4649), waiting on a Codex fix). `or2-pair` says so
  when Codex runs that way and gives the workaround: `daemon_auto_start = false` under `[features]` in
  `~/.codex/config.toml`, stop the running daemon, and start Codex with `codex --no-daemon`. It changes nothing in
  Codex's config. The app offers nothing new for Codex, whose integration is already installed.

FFI API 19 (`HostConnection.install_herdr_integration`, `HostConnection.herdr_integrations`).

## Install

**The app.** Download `or2-v0.1.3.apk` and install it over v0.1.2 (Android 14 or later, arm64); your hosts and
keys stay. It is signed with the or2 release key. SHA-256 of the APK:

```text
172fad74c782a5c109fa672163a77d69c0c3cc5588972032860587ac83ad7b5d  or2-v0.1.3.apk
```

Check it with `sha256sum or2-v0.1.3.apk` before installing. A debug build of or2 is signed with a different key:
uninstall it first (that deletes its hosts and Keystore-bound keys) and pair the hosts again.

**`or2-pair` on a host** (Linux x86_64 or aarch64, static; macOS Intel or Apple silicon), into `~/.local/bin`,
no `sudo`; running it again updates it:

```sh
curl -fsSL https://raw.githubusercontent.com/code-akram/or2/main/scripts/install-or2-pair.sh | sh
or2-pair
```

The script installs the binary for your OS and CPU from the latest release, checks it against the release's
`SHA256SUMS`, runs it once and only then puts it in place; `--version v0.1.3` pins this release. From source:
`cargo install --git https://github.com/code-akram/or2 --tag v0.1.3 or2-pair --locked`. `or2-pair --check` shows
the new Reply step without pairing or changing anything.

## Verified, and still untested

- **Verified on the owner's phone** (OnePlus 10 Pro, Android 16): Enable Reply end to end on the owner's host (an
  integration removed, offered in the Inbox, installed from the phone, Reply back after the agent restarted); the
  `or2-pair` Reply step read-only on the owner's host. The device suite passes (161 tests; the two that post
  notifications skip, because the test phone refuses the permission to a test build). A Codex review of this
  release found two minor issues, both fixed with tests.
- **Still untested**: mobile data, the Wi-Fi to mobile data handover, and background runs while the phone is
  unplugged (Doze); deferred by the owner. `or2-pair`'s install question was exercised by tests with a scripted
  herdr, not yet on a fresh host.
- **Limits that remain** are those of [v0.1.2](https://github.com/code-akram/or2/blob/v0.1.3/docs/releases/v0.1.2.md);
  see the [changelog](https://github.com/code-akram/or2/blob/v0.1.3/CHANGELOG.md).
