# or2 v0.1.9

The terminal has its own font: JetBrains Mono, bundled, with DejaVu Sans Mono for the symbols coding agents
draw. Same FFI API 23, no database migration, daemon, re-pairing or host authorization change. Updates
previous signed releases in place, preserving hosts and Keystore-bound keys. Android 14 or later, arm64;
versionCode 17.

## What's new

- **JetBrains Mono in the terminal.** The font Ghostty uses by default replaces the phone's DroidSansMono, in
  four real faces: bold and italic are the font's own, no longer synthesized. Text looks as it does in a
  desktop terminal, and the rows keep their height: cells follow the font's line spacing, as Ghostty's do.
- **Agent symbols that fit.** JetBrains Mono lacks some symbols agents print, so DejaVu Sans Mono (the
  ancestor of the Mac's Menlo) comes next, at the same width: Claude Code's `✻ ✢ ✽ ✳` spinner, `✔ ✘`, `↳`
  and `☐ ☑` sit in their cells instead of coming from mismatched system fonts. Emoji, CJK and braille still
  come from the phone.
- **`⎿` drawn.** Claude Code's tool-output bracket is in no monospace font, so it is drawn like the box
  characters of v0.1.8: a clean elbow under the `⏺` bullet.
- Both fonts are shipped unmodified with their licences (JetBrains Mono under the SIL Open Font License 1.1,
  DejaVu under the Bitstream Vera licence), listed under About or2 → Open source licenses with their full
  texts. The APK grows by about 0.7 MB.
- The UI around the terminal keeps the phone's own fonts.

## Install

**The app.** Download `or2-v0.1.9.apk` and install over the previous signed release. Do not uninstall or
clear the daily app. SHA-256:

```text
8f2ee9ac438249956a9905eb2cd1ad314ded60f1d96c9177c45c2f25a1ab9eb8  or2-v0.1.9.apk
```

Check with `sha256sum or2-v0.1.9.apk`. Debug APKs use a different signing key and cannot update the signed app.

**`or2-pair`.** Existing host installations keep working; no re-pairing is needed. This release changes
its version, not pairing behavior. Linux x86_64/aarch64 and macOS Intel/Apple silicon binaries are available
through the checksum-verifying installer:

```sh
curl -fsSL https://raw.githubusercontent.com/code-akram/or2/main/scripts/install-or2-pair.sh | sh
```

From source: `cargo install --git https://github.com/code-akram/or2 --tag v0.1.9 or2-pair --locked`.

## Verified, and still untested

- **1,087 Rust workspace tests**, no failures or ignored, with sshd, tmux, mosh and herdr required (Rust is
  unchanged since v0.1.8 apart from the version); formatting, Clippy with warnings denied, both generator
  checks (the licence data includes the fonts' notices) and `demo-gif --check` pass.
- **684 JVM tests**, no failures, errors or skips, including the vendored licence list with both fonts and their
  full licence texts; debug, device-test and signed release builds and both lints pass, with all 183 Gradle tasks
  rerun. The host native contract reports 0.1.9/API 23. The release APK is signed by the same certificate as
  v0.1.8 (SHA-256 `1418c4aa…a2a2`) and reports versionCode 17, versionName 0.1.9.
- **Device suite on the separate device-test app.** On the font change itself: **183 cases, all passed**,
  including a new check that every face draws `✻✢✽✳✶✔✘✓✗❯●…⚠↳☐☑·→λ` at the cell's width, the bold and batching
  comparisons on the real bold face, and a hardware capture reviewed on the phone. On the release build:
  183 cases, **one failure**: `terminalCannotPaintOverComposeHeaderOrOutsideItsSideMargins` found the pixel
  above the terminal at half brightness (`#19304D` for the fixture's `#336699`), as from a passing dim, not a
  glyph. It then passed ten runs alone and its class twice; the same header check failed once in the v0.1.7
  cycle. The daily app's version and update time stayed unchanged; the test packages were removed afterwards.
- Linux `dist --expect-version 0.1.9` passes: both static, stripped architectures and checksums; x86_64 runs,
  aarch64 is format-checked only. macOS binaries are built on macOS by the release workflow.
- **Published release verified:** tag `v0.1.9`; [run 37970443500](https://github.com/code-akram/or2/actions/runs/37970443500)
  built Linux/macOS and published. All six public assets downloaded: the four binaries match `SHA256SUMS` and
  their formats (static stripped Linux ELF, Mach-O per architecture); the public APK matches the SHA-256 above
  and the v0.1.8 signing certificate. The public x86_64 Linux binary reports `or2-pair 0.1.9`, and the installer
  from `main` (identical to the repository's) installed a checksum-matching `or2-pair 0.1.9` into a temporary
  directory, without touching any host installation.
- **Owner QA before release:** a signed candidate with the same change (0.1.8 / versionCode 16) was installed
  in place on the owner's phone; the owner approved it ("polished and beautiful").
- **Still owner-deferred:** mobile data, Wi-Fi handover and unplugged/Doze acceptance.
